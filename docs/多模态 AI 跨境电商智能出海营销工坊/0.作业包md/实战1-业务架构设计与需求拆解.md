# 实战1-业务架构设计与需求拆解

**多模态 AI 跨境电商智能出海营销工坊**



## 一、作业目标

做任何系统都不能一上来就写代码。本次作业要你站在**“产品经理 + 架构师”**的角度，把要做的东西想清楚、画清楚、写清楚。完成后你应该能做到：

> - 说清跨境电商出海营销有哪些真实痛点，以及我们的系统分别解决哪一个；
> - 列出一份分优先级的功能模块清单；
> - 画出一张完整的业务流程图；
> - 为前后端约定 5 个核心 API，让后面几天的开发有据可依。



>  [!CAUTION]
> 这份《项目需求规格与 API 规划书》是你后面 9 次作业的“施工图纸”。
> 写得越具体，后面越省事；
> AI 生成的内容不能直接复制，一定要自己审一遍、改成和本项目贴合的版本。



## 二、背景知识

### 2.1 我们要做什么系统

一个面向跨境电商运营的智能营销工坊：运营上传商品图，系统自动读懂商品、写出多语言多渠道文案、生成海外场景主图，最后一键打包交付。

### 2.2 业务主线

| **阶段**  | **做什么**               | **关键技术**              |
| ------- | --------------------- | --------------------- |
| ① 资产录入  | 上传商品图片，填写名称、受众、品类     | 文件上传、MongoDB          |
| ② 多模态提取 | AI 看图，输出外观、卖点、场景建议    | 多模态大模型、Prompt 约束 JSON |
| ③ 文案生成  | 按目标语言与渠道生成爆款文案        | Prompt 模板、SSE 流式      |
| ④ 生图导出  | 场景图生成、打包 ZIP、统计 Token | 异步任务、jszip、ECharts    |



## 三、操作步骤

### 步骤 1　用 AI 工具调研跨境电商营销痛点

1. 打开任意一款 AI 对话工具（通义、豆包、DeepSeek、ChatGPT 等均可）。
2. 复制下面的提示词，把方括号里的内容换成你自己的信息，发送：

``` 
你是一名资深跨境电商运营顾问。请帮我调研中国品牌出海时，
在“商品素材制作”和“海外社媒营销”两个环节的主要痛点。

要求：
1. 按“痛点 / 具体表现 / 对运营的影响 / 可以用 AI 解决的方式”四列，输出一个 Markdown 表格，不少于 6 行；
2. 重点关注：商品理解、多语言文案、场景图制作、素材交付、成本核算；
3. 每条痛点用一句话举一个真实场景例子；
4. 最后用 3 句话总结“做一个智能营销工坊”的价值。
```
把结果整理成你自己的“痛点表”，**至少保留 5 条**，删掉空泛的、改掉不贴合的。
对每一条痛点，标注本系统由哪个模块解决（资产中心、视觉理解、文案引擎、场景生图、导出与看板）。




> [!CAUTION]
>
> AI 给出的数据、案例可能是编造的。凡是出现具体数字（如“转化率提升 300%”）的，要么删除，要么注明“示例，非真实数据”。



### 步骤 2　拆分核心功能模块清单

1. 参考上面的业务主线，把系统拆成不少于 5 个功能模块。
2. 每个模块列出 3 到 5 个具体功能点，并标注优先级：P0（必须做）、P1（应该做）、P2（有时间再做）。
3. 按下面的表格格式写进规划书：
   | **模块** | **功能点**                           | **优先级** | **对应作业** |
   | ------ | --------------------------------- | ------- | -------- |
   | 资产中心   | 拖拽上传、格式与大小校验、商品信息表单、瀑布流列表         | P0      | 作业 3     |
   | 视觉理解   | AI 一键识别、JSON 结构化结果、标签展示           | P0      | 作业 4     |
   | 文案引擎   | 语言与渠道选择、Prompt 模板、敏感词拦截、流式输出、文案管理 | P0      | 作业 5、6   |
   | 场景生图   | 提示词扩写、异步生图、轮询、结果预览                | P0      | 作业 7     |
   | 导出与看板  | ZIP 打包、Token 埋点、折线图与饼图            | P1      | 作业 8     |
   | 部署交付   | Docker 化、Compose 编排、Nginx 反向代理    | P0      | 作业 9     |
4. 在表后再补充 2 个你认为“有价值但本周不做”的扩展功能（例如多用户登录、历史版本对比），标为 P2，并写一句为什么暂不做。



### 步骤 3　绘制全栈业务流程图

流程图必须包含主线 4 步：**资产录入 → 多模态提取 → 文案生成 → 生图导出**，并画出前端、后端、AI 服务、数据库之间的交互。

1. 选择一种画图方式（任选其一）：
   > 方式 A：Mermaid。在 VS Code 安装 “Markdown Preview Mermaid Support” 插件，直接把下面的代码写进 .md 文件预览。
   >
   > 方式 B：draw\.io（<https://app.diagrams.net）或> ProcessOn，用泳道图画，导出 PNG。
2. 参考的 Mermaid 起步代码如下，请在此基础上补全：
   ```mermaid
   sequenceDiagram
   
     participant U as 运营人员
     participant F as 前端 Vue
     participant B as 后端 Express
     participant M as MongoDB
     participant AI as 大模型服务
   
     U->>F: 上传商品图片并填写信息
     F->>B: POST /api/products
     B->>M: 保存商品与图片路径
     U->>F: 点击“AI 一键识别”
     F->>B: POST /api/products/:id/analyze
     B->>AI: 图片 + System Prompt
     AI-->>B: JSON(外观/卖点/场景)
     B->>M: 回写 aiAnalysis
     B-->>F: 返回识别结果
   ```
3. 在此基础上补全“文案生成（流式）”“异步生图与轮询”“ZIP 导出”三段，并至少画出 2 个异常分支，例如“图片格式不合法”“大模型调用失败”。
4. 把图（PNG）插入规划书，图下写 3 到 5 行文字说明。



### 步骤 4　规划 5 个核心 API 接口

1. 先约定统一的响应格式，所有接口都遵守：
   ```json
   {
     "code": 0,       // 0 表示成功，非 0 表示失败
     "message": "ok",    // 失败时给出可读的错误原因
     "data": { }      // 业务数据
   }
   ```
2. 选出 5 个最核心的接口。建议覆盖：商品上传、商品列表、AI 识别、文案生成、图片生成。
3. 每个接口都用下面的模板写清楚。下面是一个完整示例，其余 4 个请照着写：

   **示例：AI 识别接口**
   | **项目**  | **内容**                                                                                                                     |
   | ------- | -------------------------------------------------------------------------------------------------------------------------- |
   | 接口名称    | AI 识别商品外观与卖点                                                                                                               |
   | 请求方式与路径 | POST /api/products/:id/analyze                                                                                             |
   | 请求参数    | 路径参数 id：商品 ID（字符串，必填）                                                                                                      |
   | 成功响应    | { "code": 0, "data": { "visual\_elements": \["..."], "core\_selling\_points": \["..."], "scene\_suggestions": \["..."] } } |
   | 失败响应    | { "code": 4001, "message": "商品不存在" }、{ "code": 5002, "message": "大模型返回格式异常" }                                              |
   | 说明      | 后端读取图片并转 Base64，调用多模态模型；结果写回 Product.aiAnalysis                                                                            |
4. 每个接口都要写清 入参（名称、类型、是否必填、含义）与 出参（字段名、类型、含义），以及至少 2 种失败情形与错误码。
5. 定义一张简单的错误码表（如 4001 参数错误、4004 资源不存在、5001 服务器错误、5002 大模型调用失败）。

> [!CAUTION]
>
> 接口定好之后，作业 3 到作业 8 基本就是“按规划书把接口实现出来”，所以入参出参要写具体，不要只写“商品信息”四个字。



### 步骤 5　整理成《项目需求规格与 API 规划书》

按下面的目录组织文档，导出 PDF 或直接提交 Markdown：

1. 项目概述（背景、目标用户、价值，300 字以内）
2. 痛点分析（步骤 1 的痛点表）
3. 功能模块清单（步骤 2 的表格）
4. 业务流程图（步骤 3 的图与说明）
5. 技术选型（前端、后端、数据库、AI 服务，各写一句选型理由）
6. API 接口规划（步骤 4 的 5 个接口、统一响应格式、错误码表）
7. 本周开发计划（周一到周五，每天做什么）

> [!NOTE]
>
> 不需要写得很长，但要具体、自洽：流程图里出现的接口，必须在 API 规划里能找到；功能清单里的 P0 功能，必须能在流程图里看到。



## 四、常见问题

| **现象**        | **处理办法**                                             |
| ------------- | ---------------------------------------------------- |
| AI 给的表格太笼统    | 在提示词里加上具体场景，如“主营家居收纳的 3C 配件卖家”                       |
| Mermaid 预览不出图 | 检查缩进与关键字拼写；不行就改用 draw\.io 画图导出 PNG                   |
| 不知道接口怎么命名     | 用“资源 + 动作”风格：名词用复数，动作用 HTTP 方法表达，如 GET /api/products |
| 5 个接口不够用      | 规划书写 5 个核心接口即可，其余可在文档末尾以“补充接口”列出                     |
