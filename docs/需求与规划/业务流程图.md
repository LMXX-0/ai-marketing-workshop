# 全栈业务流程图

> 绘制方式：Mermaid 时序图（VS Code 安装 “Markdown Preview Mermaid Support” 插件即可预览）。
> 主线四段：**资产录入 → 多模态提取 → 文案生成 → 生图导出**，并覆盖 3 个异常分支。

## 一、流程图

```mermaid
sequenceDiagram
    autonumber
    participant U as 运营人员
    participant F as 前端 Vue
    participant B as 后端 Express
    participant M as MongoDB
    participant AI as 大模型服务
    participant IMG as 生图服务

    Note over U,M: ① 资产录入
    U->>F: 拖拽上传商品多图并填写名称/受众/品类
    F->>B: POST /api/products
    alt 图片格式或大小不合法
        B-->>F: { code: 4001, message: 图片格式不合法 }
        F-->>U: 表单标红并提示重新上传
    else 校验通过
        B->>M: 保存商品与图片路径
        M-->>B: 返回 productId
        B-->>F: { code: 0, data: 商品详情 }
        F-->>U: 列表新增瀑布流卡片
    end

    Note over U,AI: ② 多模态提取
    U->>F: 点击 AI 一键识别
    F->>B: POST /api/products/:id/analyze
    B->>M: 按 id 查询商品与图片
    M-->>B: 商品文档
    B->>AI: 图片转 Base64 + System Prompt
    alt 大模型调用失败或返回非 JSON
        AI-->>B: 超时 / 格式异常
        B-->>F: { code: 5002, message: 大模型调用失败 }
        F-->>U: 提示重试，不写入结果
    else 调用成功
        AI-->>B: JSON visual_elements / core_selling_points / scene_suggestions
        B->>M: 回写 Product.aiAnalysis
        B-->>F: { code: 0, data: 结构化卖点 }
        F-->>U: 彩色标签渲染外观与卖点
    end

    Note over U,M: ③ 文案生成（SSE 流式）
    U->>F: 选择目标语言与发布渠道
    F->>B: POST /api/copy/stream
    B->>AI: 模板 Prompt + 开启 stream 模式
    loop 逐段返回 token
        AI-->>B: 增量文本 chunk
        B-->>F: SSE data: chunk
        F-->>U: 打字机效果实时上屏
    end
    opt 运营中途点击停止生成
        F->>B: 前端 abort 断开连接
        B->>AI: 终止本次生成
    end
    B->>B: 正则检测敏感词与极端营销词
    alt 命中敏感词
        B-->>F: { code: 4001, message: 文案含违规词 }
        F-->>U: 提示修改语言或渠道后重试
    else 通过审核
        B->>M: 保存 MarketingAsset(type=copy)
        B-->>F: SSE done 事件
    end

    Note over U,IMG: ④ 异步生图与轮询
    U->>F: 点击生成海外场景主图
    F->>B: POST /api/images/generate
    B->>AI: 卖点与场景建议扩写英文提示词
    AI-->>B: 英文提示词（含光影与构图指令）
    B->>IMG: 下发异步生图任务
    IMG-->>B: taskId
    B->>M: 保存 MarketingAsset(type=image, status=pending, taskId)
    B-->>F: { code: 0, data: { assetId, taskId } }
    F-->>U: 骨架屏占位
    loop 每 3 秒轮询一次
        F->>B: GET /api/images/tasks/:assetId
        B->>IMG: 查询任务状态
        alt 任务失败或超时
            IMG-->>B: FAILED
            B->>M: 更新 status=failed
            B-->>F: { code: 0, data: { status: failed } }
            F-->>U: 提示重新生成，保留提示词
        else 任务完成
            IMG-->>B: SUCCEEDED + 图片 URL
            B->>M: 回写 imageUrl 与 status=done
            B-->>F: { code: 0, data: { status: done, imageUrl } }
            F-->>U: 渲染场景主图
        end
    end

    Note over U,M: ⑤ ZIP 导出与 Token 看板
    U->>F: 点击一键导出营销包
    F->>B: GET /api/assets?productId=xxx
    B->>M: 查询该商品下全部文案与场景图
    M-->>B: 资产列表
    B->>B: jszip 打包场景图 + 多语言 .txt
    B-->>F: ZIP 文件流
    F-->>U: 浏览器下载营销包
    U->>F: 打开运营数据看板
    F->>B: GET /api/stats/overview
    B->>M: 按天聚合 TokenLog
    M-->>B: Token 与成功率数据
    B-->>F: { code: 0, data: 统计结果 }
    F-->>U: ECharts 折线图与饼图
```

## 二、图说明

1. **五段主线**：资产录入阶段做格式与大小校验，非法上传直接拦截、不写库；多模态提取阶段由后端把图片转 Base64 并配合 System Prompt 强约束 JSON，结果回写 `Product.aiAnalysis`；文案生成阶段用 SSE 逐段推送，先落打字机效果再走敏感词拦截；生图阶段先扩写英文提示词，再下发异步任务并每 3 秒轮询；导出与看板阶段只读聚合文案与场景图打包下载，并按天聚合 `TokenLog` 出图。
2. **异常分支**共 4 处：图片格式/大小不合法返回 4001；大模型调用失败或返回非 JSON 返回 5002，前端提示重试且不写入结果；文案命中敏感词返回 4001，不入库；生图任务失败或超时把 `status` 置为 `failed`，保留提示词供重新生成。
3. **AI 请求只走后端**：前端不直接调用大模型与生图服务，所有调用经后端转发，由统一的 `llmClient` 记录 Prompt/Completion Tokens 与成功率，这是看板数据的来源。
4. **落库集中在后端三处**：商品入库、识别结果回写、文案与生图资产写入 `MarketingAsset`；前端刷新或重开页面后，历史素材都能从数据库恢复。
5. **接口自洽**：图中出现 7 个接口（`POST /api/products`、`POST /api/products/:id/analyze`、`POST /api/copy/stream`、`POST /api/images/generate`、`GET /api/images/tasks/:assetId`、`GET /api/assets`、`GET /api/stats/overview`），除 5 个核心接口外，其余在步骤 4 中作为“补充接口”列出，保证流程图与 API 规划能对上。
